# Smart Home Service

Тема проекта — **управление умным домом**: комнаты, устройства, события от датчиков и правила автоматизации.

## Основные сущности

- **User** — пользователь системы (имя, email).
- **Room** — комната в доме.
- **Device** — устройство в комнате (лампа, датчик движения и т.п.).
- **Event** — событие от устройства (например, `motion`).
- **AutomationRule** — правило автоматизации, реагирующее на события.
- **LogEntry** — запись в журнале срабатывания правил.

Все сущности сохраняются в PostgreSQL через Spring Data JPA.  
Связи:
- `Device` ↔ `Room` — многие устройства к одной комнате.
- `Event` ↔ `Device` — много событий у одного устройства.
- `AutomationRule` ↔ `Room` — много правил у одной комнаты.

## Бизнес‑операции

Помимо простого CRUD, сервис выполняет несколько бизнес‑операций:

1. **Обработка события и срабатывание правил**  
   `POST /api/events/add`  
   - Сохраняет событие в БД.  
   - Ищет активные правила по комнате и типу события.  
   - Для действия `turn_on_light` включает все устройства‑лампы в комнате.  
   - Для действия `notify_user` пишет сообщение в таблицу `logs`.

2. **Безопасное удаление комнаты**  
   `DELETE /api/rooms/delete?id=...`  
   - Нельзя удалить комнату, если в ней есть устройства или активные правила.

3. **Выключить все устройства в комнате**  
   `POST /api/rooms/{id}/turnOffAllDevices`  
   - Находит все устройства комнаты, устанавливает им `on = false`.

4. **Переключить состояние устройства**  
   `POST /api/devices/toggle?id=...`  
   - Инвертирует флаг `on` у устройства.

5. **Статус комнаты**  
   `GET /api/rooms/{id}/status`  
   - Возвращает комнату, список её устройств и последние события по каждому устройству.

## База данных и конфигурация

Используется PostgreSQL. Настройка через переменные окружения (без чувствительных данных в репозитории):

- `DB_URL` — URL подключения (по умолчанию `jdbc:postgresql://localhost:5432/smart_home`).
- `DB_USERNAME` — пользователь БД (по умолчанию `postgres`).
- `DB_PASSWORD` — пароль (по умолчанию `postgres`).
- `PORT` — порт HTTP‑сервера (по умолчанию `8080`).

Файл конфигурации: `src/main/resources/application.properties`.

## Как запустить

1. Поднять PostgreSQL и создать БД `smart_home` (или задать свою в `DB_URL`).
2. Установить переменные окружения при необходимости.
3. Собрать и запустить Spring Boot приложение:

```bash
mvn spring-boot:run
```

При первом запуске в БД автоматически создаются тестовые данные:
- Комнаты: *Living room*, *Kitchen*.
- Устройства: лампы и датчик движения.
- Правила: при `motion` в гостиной включить свет и записать уведомление.

## Коллекция запросов

В корне проекта есть файл **`requests.http`** с примерами запросов:

- CRUD по всем сущностям.
- Добавление события, срабатывание правил и просмотр журнала.
- Бизнес‑операции по комнатам и устройствам.

Его можно импортировать в IDE (IntelliJ IDEA / VS Code) или использовать как шпаргалку для Postman / curl.


## Безопасность

Сервис защищён с помощью **Spring Security**:

- Включена **Basic Auth**.
- Включён **CSRF** с `CookieCsrfTokenRepository` — токен приходит в cookie `XSRF-TOKEN`, а в изменяющих запросах его нужно передавать в заголовке `X-XSRF-TOKEN`.
- Пользователи хранятся в таблице `auth_users` (модель `AuthUser`).

При первом запуске создаются два пользователя:

- `admin` / `Admin123!` — роль `ADMIN`
- `user` / `User123!` — роль `USER`

Права доступа:

- `POST /api/auth/register` — доступно **без авторизации** (регистрация нового пользователя).
- `GET /api/**` — доступны ролям `USER` и `ADMIN`.
- Любые изменяющие запросы (`POST`, `PUT`, `DELETE` на `/api/**`) — только для роли `ADMIN`.

В будущем поверх этой модели можно добавить аутентификацию по логину/паролю (формы, JWT и т.п.), т.к. уже есть:
- сущность пользователя (`AuthUser`);
- хранилище пользователей (`AuthUserRepository`);
- `UserDetailsService` (`AuthUserDetailsService`);
- `PasswordEncoder` (`BCryptPasswordEncoder`).
